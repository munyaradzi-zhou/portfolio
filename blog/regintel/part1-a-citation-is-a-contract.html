A citation is a contract, not a courtesy

RegIntel: answers you can check · Part 1 of 5

TL;DR — RegIntel answers regulatory questions about FDA, ICH and EMA guidance. A model writes the answer; plain Python decides whether you get to see it. Every quote must be verbatim in a retrieved passage and every number must appear in a quote, or the statement is removed. Building that check taught me more about my corpus than about my model: the first verifier rejected 28 real quotes because of how PDFs store text, and the best fix of the whole project cost zero model calls.

In most domains a slightly wrong answer is an inconvenience. In drug regulation it can be a missed reporting deadline. "Serious unexpected suspected adverse reactions must be reported within 7 days", with a citation, reads as authoritative. If the cited sentence actually says 15, the citation has made the error more convincing, not less.

That was the design brief for RegIntel: a question-answering system over 23 public guidances (9 FDA, 8 ICH, 5 EMA, EU GMP Annex 11), CDISC terminology and a quarter of FDA adverse-event reports, deployed on Azure. The premise I started from: in a regulated domain, a confident wrong answer is worse than no answer.

Asking for citations is not enough

A retrieval-augmented system gives the model passages and asks it to answer from them. Asking it to cite is the obvious next step, and it helps. But a citation is a claim the model makes about its own answer. It can point at the right passage and still misquote it, carry a number the passage does not contain, or quote a sentence that does not support the conclusion.

So the contract changed. The writer (gpt-5-mini, structured output) does not return prose. It returns a list of short statements, and for each statement, which passage it relies on and a quote: words copied from that passage.

DraftAnswer
  answerable: true
  statements:
    - text: "The 90% confidence interval ... should be contained within 80.00-125.00%."
      citations: [{passage: 1, quote: "the 90% confidence interval for the ratio of the test and
                   reference products should be contained within the acceptance interval of 80.00- 125.00%"}]

Then code checks it, before anyone sees it:

  1. The passage exists. A model cannot cite passage 9 when it was given eight.
  2. The quote is in the passage. Character by character, in order.
  3. Every number in the statement is in one of its quotes, compared by value.

A statement that fails is removed. An answer with nothing left is withheld and labelled not grounded. An answer where the model itself said the passages do not cover the question is labelled declined. The user sees which happened.

The first verifier rejected the truth

The first run on my 60-question golden set: 89% of drafted statements verified, 28 quotes rejected. I assumed a misbehaving model. Then I read the rejections.

Most were real quotes. The PDFs had stored the text in ways no human sees:

  • Words split by the extractor: "proce dure", "doc uments".
  • Hyphenation across line breaks: "life-" + "threatening".
  • Odd spacing inside numbers: "80.00- 125.00%" in the EMA guideline.

The model, reasonably, had written the words as words. My check was comparing a cleaned human sentence with a dirty machine extraction and calling the human a liar.

Verifier v2 normalises both sides (Unicode form, dashes, curly quotes, case), removes hyphens, and compares ignoring spaces. The characters must still appear in order, so a paraphrase still fails. Numbers compare by value: 80 equals 80.00, .025 equals 0.025. I re-ran it on the identical drafts:

Same 60 questions, same draftsVerifier v1Verifier v2
Statements verified0.8910.940
Quotes rejected2815
Extra model calls–0

The biggest quality gain of the project came from a dozen lines of string handling.

Tell the model the test before it sits it

The remaining rejections were real misquotes, so the next step was the prompt. It now states the rules the verifier enforces: quote character for character; one unbroken stretch, with "..." where you leave words out; every number in a statement must be in one of its own quotes; if the sentence you quote refers to a number given elsewhere, cite that place too.

ChangeStatements verifiedQuotes rejected
Prompt v1, verifier v20.94015
Prompt v2: unbroken quotes; restated numbers cite their source0.96311
Prompt v3 + footnote fix (below)0.9715
Prompt v4: don't stretch a general rule0.9802

The rules never changed. The model just knew them.

The verifier is the best data-quality detector I have

Several rejections pointed at the corpus, not the model.

Footnotes inside sentences. FDA guidances put footnotes at the bottom of the page, and the extractor put them right where the page broke, so a sentence ending "…usually 80.00" on one page and continuing "percent to 125.00 percent…" on the next had a footnote wedged in the middle (simplified here). No model can quote that sentence faithfully. The chunker now separates each page's footnotes, re-joins a sentence broken by a page boundary, and appends the footnotes after it. Rejected quotes fell from 11 to 5, and retrieval improved as a side effect.

Equations as Ethiopic script. The knowledge base kept retrieving "passages" made of Tamil, Syriac and Ethiopic letters. They were equations from the FDA statistics guidance, set in math fonts that the extractor mapped to random scripts. Those runs now become a [formula] placeholder, and chunks that are mostly tables or formulas are dropped.

Each of these broke quote verification before it broke anything else. A check that demands exact text is a microscope on your data.

Numbers are where it matters most

The number check is the one I'd keep if I could keep only one. In the prompt-injection evaluation (Part 6), one attack planted a passage claiming a "70–130%" bioequivalence range. The statement repeating it was dropped, not by a security filter, but because no retrieved passage contained 70 or 130. A grounding check turned out to be a security control too.

What it doesn't catch

Question na-06 asked whether EU GMP Annex 11 sets validation requirements for machine learning models. The passages contained Annex 11's scope: it "applies to all forms of computerised systems used as part of GMP regulated activities". The writer concluded that Annex 11 therefore applies to machine learning models.

Every quote was verbatim. Every number checked out. The verifier passed it. The conclusion was the model's, not the guidance's, because the guidance never mentions machine learning. A string check cannot see the gap between a true quote and a false inference. That needed a different tool, and Part 3 is about it.

Takeaways

  • Make citations a contract the code checks, not a courtesy the model offers. Quotes verbatim, numbers by value.
  • When a strict check fails, read the failures before blaming the model. Mine were mostly the PDF.
  • Change one thing at a time on identical inputs: re-verifying the same drafts showed the gain was the verifier, not luck.
  • Tell the model exactly what will be checked.
  • Verification catches misquotes and wrong numbers. It does not catch wrong reasoning.
